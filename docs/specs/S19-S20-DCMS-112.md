# DCMS-112 — Khám theo Visit và tài liệu lâm sàng

Ngày chốt: 26/10/2026. Nguồn: DCMS-110/111/112/104, handoff DCMS-113/114/115.

## Luồng và phạm vi

S19 mở `/visits/{visitId}` từ hàng chờ dùng đúng Visit do DCMS-111 tạo. Header lấy Patient/lịch/bác sĩ/chi nhánh/lý do tiếp nhận từ server. Chỉ bác sĩ được phân công, còn hoạt động và có membership `CanDentist` tại chi nhánh được bắt đầu, lưu, xác nhận và review. Trợ lý cùng chi nhánh được đính kèm/đọc tài liệu; không được sửa khám hay review. Kiểm lại quyền ở mọi request, kể cả retry/content.

Start chuyển Visit Queued → InProgress và Appointment CheckedIn → InProgress cùng transaction; giữ reservation. Không tự tạo Visit, hồ sơ điều trị, actual, phí hay lịch. Sử dụng requestKey + expectedVersion, advisory transaction lock hiện có, concurrency token và audit. Cùng key/payload replay; key khác payload hoặc version cũ trả 409 MSG111, không ghi một phần.

Lưu một examination hiện hành mỗi Visit và giữ snapshot từng lần ghi. Nháp cho phép thiếu nội dung. Xác nhận yêu cầu triệu chứng/lý do khám, findings, chẩn đoán và xác nhận tiền sử/dị ứng/thuốc. Mỗi nhóm là Unknown/None/Present, Present cần nội dung; Unknown khác None và được giữ khi chưa xác minh. Xác nhận phải có người xác minh các nhóm (có thể xác minh vẫn Unknown). Răng theo FDI gồm răng vĩnh viễn và răng sữa; cho phép ghi vùng thay răng. Mỗi finding có răng/vùng và tình trạng. Sau xác nhận chỉ đọc; bổ sung có phiên bản/lý do thuộc DCMS-115.

Lượt mới có snapshot tiền sử mới nhất để bác sĩ xác minh lại; không thay nội dung lượt cũ. Lịch sử khám đọc theo Patient trong chi nhánh đang được cấp quyền. Mở hồ sơ điều trị cũ dùng engine của nhánh Vinh (DCMS-96/97/98/99), không tạo lại hồ sơ vì đổi ngày. Handoff trả visitId/patientId/branchId/version, findings, diagnosis, teeth, documents và source cũ; hai hướng Counseling và Treatment không yêu cầu phí/actual/thanh toán. Own-record tổng hợp không thuộc task này.

## Tái sử dụng

Tích hợp nền treatment đã có từ `origin/vinh`, S20 từ `origin/TriNM`; giữ provenance trong Git. S20 list/viewer/upload được nhúng trong S19 và trang tài liệu Patient, bỏ phụ thuộc preview ở đường chạy thật. Không coi test mock/Done Jira là bằng chứng tích hợp.

## API

| API | Contract |
| --- | --- |
| GET `/api/visits/{id}/examination` | Context, examination nháp/xác nhận hoặc null, allowedActions, latestHistory |
| POST `/api/visits/{id}/start` | patientId, expectedVersion (Visit), requestKey |
| PUT `/api/visits/{id}/examination` | patientId, expectedVersion (Visit), requestKey, symptoms, medicalHistory/allergies/medications {state, detail, verified}, findings [{tooth?, region?, condition}], diagnosis, notes, confirm |
| GET `/api/visits/{id}/clinical-history` | Khám cũ của cùng Patient/chi nhánh, snapshot bất biến; không gộp thành lần khám mới |
| GET `/api/visits/{id}/clinical-handoff` | Dữ liệu đã xác nhận cho 113/114/115; không tạo side effect |
| GET `/api/patients/{id}/document-contexts` | Patient và Visit/dossier/plan có quyền; IDs do server cung cấp |
| GET `/api/clinical-documents` | patientId, visitId?/dossierId?/planId?, type?, from?, to?, page, pageSize; constraints/actions |
| POST `/api/clinical-documents` | multipart files (1–10), metadata JSON tương thích S20; một file cũng trả `document`; batch trả `documents` với lỗi theo file |
| GET `/api/clinical-documents/{id}` và `/history` | Metadata/state/audit có quyền |
| GET `/api/clinical-documents/{id}/content` | Chỉ Ready; kiểm quyền Patient + nguồn mỗi lần; không public URL, no-store, nosniff, attachment mặc định |
| POST `/api/clinical-documents/{id}/review` | patientId, visitId, expectedVersion (document), requestKey; chỉ bác sĩ của Visit và file Ready |

Metadata: patientId, visitId bắt buộc cho upload ở task này; dossierId/planId tùy chọn phải cùng Patient/branch và cùng nhau; investigationId/consentVersion chưa có nguồn thẩm quyền thì từ chối. documentType: XRay/IntraoralPhoto/LabResult/ConsentForm/Referral/Other; source Clinic/External; sourceDate; description ≤1000; requestKey.

JPEG/PNG/PDF, ≤20 MiB/file, ≤10 file/request. Kiểm MIME, extension và chữ ký nội dung ở server trước khi lưu. File private ngoài repo qua `ClinicalDocuments:StoragePath`. Trạng thái PendingScan/Ready/Rejected; scanner là cổng riêng, thiếu scanner hoặc lỗi scan giữ PendingScan và cấm content/review. Không có API nhân viên tự chuyển Ready. Adapter ClamAV dùng INSTREAM, cấu hình host/port; chỉ CLEAN mới Ready. Upload không tự review: reviewedAt/by/visitId chỉ do command bác sĩ riêng. File lỗi trong batch có lỗi riêng, các file hợp lệ vẫn giữ kết quả. Retry batch dựa metadata + nội dung/thứ tự; không nhân file. Audit upload/scan/read/review, không lộ private path.

400 validation, 401 session, 403 permission, 404 nguồn không có/không cùng Patient, 409 stale/key conflict/trạng thái chưa phù hợp, 503 dependency chưa sẵn sàng. Không đưa IDs/version thành ô nhập nhân viên.

## Nghiệm thu cần bằng chứng

API thật + PostgreSQL schema riêng: check-in → start → save draft → reopen → confirm → handoff; nhiều Visit không ghi đè; mở dossier cũ; retry đồng thời/stale; Patient/branch/role/source giả bị chặn; fake extension/signature/size/batch bị chặn; PendingScan/Rejected không content/review; Ready download và review tách biệt; quyền bị thu hồi chặn cả replay. UI thật từ hàng chờ qua S19/S20 và hai nhánh handoff. Ghi rõ scanner thật/stand-in, backend thực hay mock; chỉ báo pass cho phần đã chạy.
