# DCMS-92 — S24 (Web chỉ định quay lại) & S41 (Mobile My Medical Records)

Phụ trách: Tống Nguyên Tuấn. Spec: [S24](../specs/S24-FOLLOW-UP-INSTRUCTION-WEB.md), [S41](../specs/S41-MOBILE-MEDICAL-RECORDS.md). Backend instruction/projection lấy từ nhánh DCMS-97 (Vinh) đã merge vào nhánh làm việc; task này là UI/UX integration, không viết backend engine.

## 1. Navigation path

### S24 (Web staff)
1. Đăng nhập tài khoản Dentist (`/sign-in`) → **Bệnh nhân** (`/patients`) → mở hồ sơ bệnh nhân (`/patients/{id}`) → tab **Điều trị & Thanh toán** → **Mở đợt điều trị** (`/patients/{id}/dossiers/{dossierId}`).
2. Khối **Chỉ định quay lại (S24)** trong `DossierPage`: danh sách chỉ định của bệnh nhân + nút **Tạo chỉ định** (khóa khi kế hoạch chưa chốt/độn viên chưa đồng ý).
3. Sau khi lưu → trạng thái `NeedsBooking` → **Tìm khung giờ (S11)** mở `BookingDrawer` với bối cảnh `followUpId` (kind `FollowUp`, patient/nha sĩ/thời lượng/cửa sổ khóa theo chỉ định) → chọn slot → **Xác nhận đặt lịch** → panel tải lại instruction từ server.

### S41 (Mobile)
1. Đăng nhập tài khoản Public (S01) → Home tài khoản (`(account)/home`) → nút **Hồ sơ y tế của tôi** → `(account)/medical-records`.
2. Chọn một hồ sơ → `(account)/medical-records/[dossierId]` → back về danh sách (vị trí cuộn giữ nguyên do stack giữ màn hình).

### Ca S24 (AT37) — `web/tests/follow-up-instructions.spec.ts`

1. **Handoff S11 + không Booked sớm:** mở S24 từ đợt điều trị → “Tìm khung giờ” mở `BookingDrawer` với kind `FollowUp`, bệnh nhân/khóa nha sĩ/thời lượng/cửa sổ theo chỉ định; assert payload `POST /api/appointments` có `followUpId` = instruction ID, `kind=FollowUp`, `durationMinutes=30`, `attendee.patientId=123`, `requestKey` là UUID. Server mock delay 700 ms → UI vẫn hiển thị “Chưa đặt lịch” trong lúc chờ; chỉ sau response + read-back `GET /api/follow-up-instructions` mới hiện “Đã đặt lịch” + mã lịch `AP-TEST` (không set state local).
2. **Validation + giữ form + requestKey:** window `target < earliest` → chặn client, **không** gọi API; sửa hợp lệ → server trả 400 MSG229 → form giữ nguyên giá trị (kiểm bằng `toHaveValue`), drawer mở; gửi lại thành công → drawer đóng, trạng thái từ response (MSG231); `requestKey` của lần 4xx và lần sau **khác nhau**. Payload tạo đúng `source {dossierId,itemId,stepId,visitId:null,activityId:null}`, purpose, window, duration.

### Ca S41

- Mobile không có test runner (chỉ `tsc --noEmit` theo scaffold) — kiểm thử tương tác cần Expo + backend thật, **chưa chạy** trong môi trường này (không có Docker/PostgreSQL để bật API).
- Dashboard API thật (`/api/patient-links/me`, `/api/patients/me/treatment-summary`, `/api/me/appointments`) chưa được chạy end-to-end tại chỗ do thiếu Docker; các suite Playwright dùng backend thật (`accounts`, `patients`, `recovery`, `customer-appointments`, `support-inbox`) cũng chưa chạy vì thiếu `.env` + `E2E_DEMO_PASSWORD`. Cần chạy lại khi môi trường DB sẵn sàng.
